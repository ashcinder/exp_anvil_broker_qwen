# 实验28：半衰期分阶段搜索（40000 CTX）

目标：找到当前构造负载下，Relay与Relay+TDR各自表现较好的半衰期，以及实际近优区间。
不以“必须出现U型”作为成功标准，不改变负载或另一参数来追求曲线形状。

## 为什么不直接只扫100～1000

100,150,200,250,300,350,400,450,500,600,700,800,1000可以检查长区间，却无法比较
历史上Relay较好的4、20块和总次数进入平台的50块。长区间密集扫描之前，应先保留短端对照。

40000 CTX的实测运行通常约600块，1000块半衰期会显著保留早期记忆。
以600块为例，旧观测权重为2^(-600/h)：h=100时约1.56%，h=400时约35.36%，
h=1000时约65.98%。因此1000并不保证进入另一侧U型右支；它可能只是近似慢记忆极限。
这次搜索确定的是有限时长的策略表现，而不是长时间稳态全局最优。

## 固定条件

- 使用当前D盘仓库exp025的pipeline、brokerlab策略和完整性校验，实验单独保存到exp028。
- 16分片、50 broker、200 user；每点每轮40000 CTX；每broker每分片45 ETH。
- Top-up + 无限历史EWMA，q_min=0.3、epsilon=0.95锁定；至少5个观测块预热。
- 单侧Top-up；TDR事件间隔10块、超时20块；链出块1秒；B2E关闭。
- 从ETH_cleaned.csv选流；前30%保留，后70%热点11/3每1600笔轮换，避免源目的同分片。
- 设定rate=120 CTX/s；实际吞吐和提交块跨度另行记录。
- 主指标C=Relay CTX+完成TDR搬运次数，每次搬运计一次；辅指标Relay CTX。
- C是等权次数，不是gas、字节或时延成本；如需成本权重，另行预先指定，不能看完结果再改。

历史submit_regime_shift使用的代码与当前管线并非保证相同，其旧重复又多为route_seed=7。
本实验继承其问题设置，使用当前校验后的实现重新测量参考点，**不直接合并旧数值**。
当前exp025在跑时，不并行启动本实验；等其结束后再运行。勿在一个实验运行期间改共用源码。

## 阶段一：推荐粗扫

网格：**2,4,8,10,20,50,100,200,400,800,1000**。
默认每点只跑1轮，11次运行，共44万用户CTX。每次约10分钟时，串行约2小时；实际以机器速度为准。
这轮用于查看初步数值趋势，不估计运行波动或统计显著性，也不生成自动精扫建议。

同一轮各参数共享同一workload和route_seed=7。以后需要重复时，可显式传入`--rounds 6`，种子为7,17,27,37,47,57。
各次重新起链、重新充值；每轮参数顺序确定性随机化，以减小固定顺序与机器状态漂移的混淆。
同一负载的不同路由种子是配对运行条件，不代表6份独立主网负载。

## 阶段二：结果驱动精扫与独立确认

粗扫完成后查看`out/coarse/<时间目录>/analysis/analysis_report.md`和`half_life_trend.png`。
单轮先人工查看数值趋势。至少3个共同完整轮次后，分析脚本才会给出`suggested_fine_command.txt`，它只是建议，不自动开始运行。

- 若最低值在短区间：例如围绕4～20块搜索，并保留上阶段最优点和20块参考点。
- 若最低值在50～200：例如20,30,40,50,75,100,150,200；不必先把400～1000全部扫密。
- 若50～1000相差不足1%：先判断平台，优先确认平台起点；不把均值的小幅波动当作U型。
- 若1000仍明显更好：对当前40000 CTX而言只是边界最低点；先做时长诊断，不无限扩大h寻找预定形状。

例如粗扫支持20～100附近值得继续细扫时，手动执行：

```powershell
python .\run.py --stage fine --values 10,20,30,40,50,75,100,150 --rounds 10
```

上面显式指定每点10轮，使用新种子1007,1017,…,1097，输出到`out/fine/`。
所有stage的默认轮数现均为1；需要重复时必须指定`--rounds`。
示例网格不是预先认定的最佳范围，应根据粗扫结果选择；可以用`--rounds`调整轮数。
保持q_min、epsilon、资金、交易量、负载、执行管线一致。

## 续跑与提前查看结果

中断后使用原stage、values、rounds、seed和--set选项续跑。没有改动默认参数的粗扫示例：

```powershell
python .\run.py --resume '.\out\coarse\<原时间目录>'
```

精扫续跑还必须保留`--stage fine --values ...`。配置、负载或执行源码变更会拒绝续跑。
失败任务重新运行；失败数据不进入统计。重复参数点不会并行起链。

```powershell
python .\analyze.py --source '.\out\coarse\<时间目录>'
python .\analyze.py --source '.\out\coarse\<时间目录>' --verify-raw
```

结果包含每次运行的Relay、TDR、总和、原始台账、block_stats及守恒门；分析输出：

- `parameter_summary.csv`：各点均值、中位数、四分位数、标准差、实际提交跨度。
- `balanced_summary.csv`：各参数共同完整轮次的统计；未完成实验不凑齐样本。
- `paired_differences.csv`：相同route_seed下与各指标样本最低点的差值及探索性95%bootstrap区间。
- `half_life_trend.png/svg`：每点只有1次时，直接展示Relay和总和的观测趋势；横轴使用半衰期的对数刻度。
- `half_life_boxplots.png/svg`：有重复样本时生成箱线图，n标明实际完成重复数。
- `decision.json`：两个指标的样本最低点、总和在最低均值1%以内的候选、Pareto候选。
- `suggested_fine_command.txt`：新种子精扫建议；需至少3个共同完整轮次，smoke不生成建议。

bootstrap区间没有校正同一数据挑选赢家和多重比较，不可用于宣称正式显著性。
1%是预先固定的工程容差；“落在容差内”不代表已证明统计等效。

## 怎样判断结果

1. 两指标各自排名，不把Relay的最低点当成总和的最低点。
2. 两端相对中间持续变差，且独立种子精扫能重现，才有更强的U型证据。
3. 全曲线单调下降：报告边界最低值，不称为已定位内点最优。
4. 长区间近似平台：报告近优范围；可选其中较短、响应较快的半衰期。
5. 若目标对两个指标都敏感：查看Pareto候选或事先定义Relay上限，避免事后改指标选赢家。

若要研究h=800/1000的长期效果，另做长时段验证，使**实测有效观察跨度至少约3～5个最大半衰期**，
并保持热点按相同块级节奏切换。不能只增加CTX数但仍沿用shift_period_frac=0.04，
否则每次热点持续交易数也会变长，同时改变了负载条件。更长负载也需检查可用trace、
选流组成和资金约束，因此未在本40000 CTX实验中自动扩大负载。
