# 实验设计 v2：先审阅参数，再自行运行

此版本按用户要求修改评价口径；本轮仅修改代码、配置及进行不启动Anvil的检查，没有运行新的链上实验。旧预实验数据保持原样。

## 1. 两个主要评价指标

**总额外跨片CTX数 S = Relay用户CTX数 R + 资金调整CTX数 A，越小越好。**

资金调整CTX就是broker从一个分片子账户向另一个分片子账户移动资金。一次 src→dst 计1个CTX；其burn、mint两个执行腿合计仍为1个CTX。一次调整事件若搬动5对账户，则A增加5，而非1或10。所有主动策略均计自己的调整CTX，不能只把TDR的额外开销计进去。BrokerChain无调拨，A=0。

例如：100笔用户交易中，30笔走relay，策略另外发起10笔资金转移，则S=40；普通broker成功服务的70笔不再加到S中。如果固定用户交易数N，则N+S与S具有相同排序。

**Broker总净利润 P = 已确认broker服务数 B × 每笔留存费 f − 资金调整CTX数 A × 单笔调整模型费用 c，越大越好。**

主报全部broker的总利润，另报平均每broker利润及每个broker的明细；不能挑单个最赚钱broker代表整组。relay用户交易不产生broker服务留存费。模型费用不会从钱包运行余额扣除；实际Anvil gas费另列，不能当作真实付费网络利润。

不把S与P再加权为一个分数：若S更少但利润更低，要同时呈现权衡。以失败CTX数=0、全部资金/回执完整性检查通过作为有效比较前提。事件次数、参考用户CTX、延迟、gas和余额CV降为辅助指标。

## 2. 所有方法共用的正式参数

| 参数 | 提议值 | 目的/含义 |
|---|---:|---|
| 分片数 | 16 | 与原分片环境一致 |
| broker数 | 50 | 全部方法一致 |
| 每broker每分片初始资金 | 45 ETH | 每broker共720 ETH，全部broker共36000 ETH |
| 每方法每轮用户CTX | 40000 | 50×800，是总选流目标，不保证每broker恰好处理800笔 |
| 到达速率 | 120 CTX/s | 指派发负载速率，不是承诺实际吞吐 |
| 重复 | 3整轮 | 同轮5方法使用同一负载、route seed；种子7/17/27 |
| 数据 | trace/ETH_cleaned.csv | 固定选流seed=42，金额范围0.01～10 ETH |
| 热点开始 | 第12000笔以后 | 前30%保留自然目的分片 |
| 热点位置 | 分片11、3交替 | 后70%每1600笔切换；强度1，避免同源目的分片碰撞 |
| 出块时间 | 1秒 | 方法使用同一执行平台 |
| 调整事件最小间隔 | 10逻辑块 | 从上次事件开始计时，并非事件完成后再等10块 |
| 活跃事件数 | 每broker最多1个 | 已有调整未结束时不新开事件 |
| 每事件转移数上限 | 15 | n−1；不是整个运行只能调整15次 |
| 初始错峰 | broker_idx % 5块 | 主动方法使用同一错峰规则 |
| 调整超时 | 20逻辑块 | 与真实执行回执配合核对 |

每方法使用独立重启的Anvil链，串行运行，轮次间轮换方法顺序。资金调拨必须使用已确认且未预留余额；不能直接改余额、提前使用未到账资金。

## 3. 五种方法的独立参数

| 方法 | 决策和触发方式 | 提议参数 | 额外CTX如何计数 |
|---|---|---|---|
| BrokerChain-core | 普通broker服务+relay兜底，没有主动调整 | 无资金调整策略参数 | 只有R，A=0 |
| Horcrux思想适配 | 成功服务产生src→dst补偿需求；反向需求抵消；有补偿债务时按可用资金聚合偿还 | 债务>0即可规划；无预测窗口、无额外幅度阈值；共用10块间隔 | 每个完成的源→目的补偿转移计1 |
| Shaduf AB适配 | 目的余额不足以支付近期最大单笔请求时，从绑定来源补缺口；优先可搬金额较大的来源 | 全部两两绑定；每方向初始额度3 ETH（45/15）；窗口20块；额度随完成转移更新、不重置 | 每个完成的绑定资金转移计1 |
| LAI(1)适配 | 根据近期目的付款总金额形成需求比例，与旧连续分配插值，搬移实际余额与目标的差额 | γ=1；A=1·I；保留约38.2%旧分配+61.8%新需求；窗口20块；5%均匀底仓 | 每个完成的盈余→缺额转移计1 |
| TDR Top-up+EWMA | 对严重缺额账户补足，资金来自达到盈余阈值的账户 | EWMA半衰期20块；最少观测5块；无限记忆；q_min=0.3；epsilon=0.95；two_sided=false | 每个完成的Top-up转移计1 |

TDR实际代码在two_sided=false时仍同时筛选可用来源：接收方余额低于目标的5%，来源余额高于目标的195%；再在匹配账户间补缺口。epsilon=0.95不是“缺5%就触发”。q_min=0.3表示每个分片的目标余额至少为总可用资金×0.3/16；先按需求生成目标，再补足低于该底线的账户并从其他目标中摊回缺额，不是简单的30%均匀+70%需求混合。

这组数沿用已跑通的25/26设置和上批适配参数，不是按新主指标调参得到的最优参数。基线自身决策差异保留；共同限制的是执行条件，而不是给所有算法强行套TDR的触发阈值。

Horcrux、Shaduf为资金策略适配，未复现其完整PCN协议；LAI连续公式可核验，但需求换算及链上执行属于适配。BrokerChain也是核心机制基线。论文写法应保留这些边界。

## 4. 收入与费用参数——需要重点判断

| 参数 | 提议值 |
|---|---:|
| 用户手续费F | 21000000 wei |
| broker留存份额 | 10% |
| 每笔broker成功服务留存费f | 2100000 wei |
| 每笔资金调整CTX模型费用c | 21000000 wei，整笔费用，不按2个执行腿重复计费 |
| 费用敏感性 | c=0、2100000、21000000、210000000 wei |

默认c/f=10：每笔额外调整至少增加10笔broker服务，才能覆盖模型费用。因此不能仅凭Relay减少断言利润增加。保留这个默认值是为了与实验26可比，并不表示它已被证明是实际部署的费率。费用扫描是固定轨迹的事后核算，不是不同实际gas价格下重跑。

若认为单笔资金调整的成本不应等于用户总手续费，请先改 `exp.profit_tdr_cost_wei`；所有方法使用同一个值，不能分别设不同费率。

## 6. 你自行运行

配置文件是同目录 `config.yaml`。这次修正了入口对epsilon、EWMA半衰期和q_min的固定覆盖，直接读取配置中的 `exp.tdr_*`；`exp.arms` 已移除，单独修改旧arms字符串不再是本实验的调参方式。

从D盘项目根目录运行，仅预览参数、不启动链：

```powershell
Set-Location 'D:\BaiduNetdiskDownload\exp_anvil_broker_qwen\exp_anvil_broker_qwen'
python experiments/exp030_five_method_rebalance/run.py --dry-run
```

你判断好上述设置后，自行运行正式实验：

```powershell
python experiments/exp030_five_method_rebalance/run.py
```

小规模检查仍可使用 `--smoke`（16分片/1broker/80CTX/1轮/5ETH/rate=5）或 `--pilot`（16分片/4broker/1000CTX/2轮/5ETH/rate=16），算法参数和费率保持相同，但资金规模与负载不同；参数预览可组合 `--pilot --dry-run`。

运行完成后自动生成中文报告及图，不必再手动执行分析脚本。新结果保存到新的out时间戳目录，不覆盖旧预实验。由于代码/配置口径已更新，不续跑旧版本目录。

主文件：`primary_metrics.csv`、`primary_summary.csv`、`RESULTS_CN.md`、`DETAILED_RESULTS_CN.md`、`comparison.png`。`design.json`保存本次实际参数。逐broker的利润和总CTX保存在各任务的`broker_metrics.csv`。
