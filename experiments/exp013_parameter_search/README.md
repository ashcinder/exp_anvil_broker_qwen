# 实验 13：分片集中度场景下的分阶段参数搜索

以实验 12 的映射负载与执行管线为模板。实验 12 保持独立；本目录搜索
Plain、Valve、Proportional、硬窗口 Topup、EWMA Topup 五种方法。
用户所称 RWMA 对应现有 EWMA Topup 实现，本实验不改变估计器与再平衡公式。

当前默认：金额 0.05～5 ETH，每个搜索/验证 trial 为 10,000 CTX、一个种子跑一轮。
保留粗搜、细搜、留出验证；入选候选在一个留出区间另验证一轮，不再使用多窗口、多种子重复。
本次更新仅调整配置，未启动正式搜索。旧输出保存的冻结配置不会随本文件改变；
要采用新参数，请新建运行，不要对旧输出使用 `--resume`。

## 确认后的候选参数

| 维度 | 完整候选值 |
|---|---|
| 每 broker 每分片余额，ETH | 0.1、0.2、0.3、0.5、0.7、1.0、1.5、2.0、5.0 |
| Valve 倍率 | 1.1、1.2、1.3、1.5、1.7、2.0、2.5、3.0 |
| 三种需求策略的 epsilon | 0.1、0.2、0.25、0.4、0.5、0.7、0.9、0.95 |
| Proportional / Topup 硬窗口，块 | 1、2、4、8、16、32、64 |
| EWMA 半衰期，块 | 1、2、4、8、16、32、64 |

epsilon 必须小于 1；供给侧 surplus_epsilon 同步使用相同值。
EWMA 的硬窗口字段不参与需求估计，不与半衰期做笛卡尔积。
Plain 每个场景只作一组训练对照，Valve 的八档只跑一次，不随窗口重复。
原实验 12 的 EWMA 半衰期 20 不在本次确认的网格中。

7 种映射如下，地址归属在每次运行中固定：

| 名称 | 后缀位数 | 新增桶分给 | 理论地址占比 |
|---|---:|---|---|
| uniform4 | 4 | 无新增桶 | 每片 6.25% |
| one_hot5 | 5 | S0 | S0 53.125% |
| one_hot6 | 6 | S0 | S0 76.5625% |
| two_hot5 | 5 | S0、S1 | 各 28.125% |
| two_hot6 | 6 | S0、S1 | 各 39.0625% |
| three_hot5 | 5 | S0、S1、S2 | S0 21.875%，S1/S2 各 18.75% |
| three_hot6 | 6 | S0、S1、S2 | 各 26.5625% |

规则：取低 b 位作为桶号，桶 0～15 按原编号进入 S0～S15，
其余桶按 `(bucket - 16) % 热点数` 轮流进入指定热点。
5 位新增 16 桶无法被 3 整除，因此三热点权重略不相等；6 位新增 48 桶可均分。
理论地址占比不等于实际交易占比，也不保证单向净流或实际链上拥堵。

## 固定负载与基础设施

- 未 clean 的 `trace/ethereum_202509.csv`，金额过滤 0.05～5 ETH，允许合约端点。
  只重放地址、金额和方向，不执行原始 calldata。

- 每个搜索/验证 trial 都是 10,000 CTX（50 brokers × 200），包括粗搜；目标 120 CTX/逻辑块、1 秒/块。
- 每分片 2,100,000 gas/块，约 100 个普通转账段；TDR 与业务共享区块容量。
- χ=10 块、TDR timeout=20 块、q_min=0.1、target_cap=0、min_reserve=0。
- 端口 14600～14615，链 ID 从 63000 起；每个 trial 重启全新链。
- 每次只运行一个 trial；和其他实验并跑可能污染墙钟指标，正式测量应保持主机条件一致。
- 共享 exp003 的交易执行、对账和容量采集；不复制/重写策略实现。

保持实验 12 的跨片子系统口径：片内交易被记录后过滤，不占模拟区块。
各映射使用同一候选池，但最终 CTX 集合、金额与源时间跨度可能不同。
相同映射、相同数据区间下，全部余额、方法、参数、种子使用同一份固定 CTX 输入。
统计中的原始交易顺序保持不变；为了抵消执行先后影响，只对 trial 的运行顺序使用固定种子打乱。

## 分阶段算法

### coarse：粗搜

每个“余额 × 映射”场景运行：

- Plain 1 组。
- Valve 全部 8 个倍率。
- Proportional / Topup / EWMA 各搜索 epsilon `[0.1, 0.5, 0.9, 0.95]`
  × 记忆尺度 `[4, 16, 64]`，每方法 12 组。

每场景共 45 组，63 个场景共 **2,835 组**。训练种子固定为 7。
粗搜、细搜均只使用种子 7 各跑一轮，每组 10,000 笔；已完成的相同组合不重复运行。

### refine：邻域细搜与补充探索

在每个场景、每个需求策略内部，按 Relay 比例、额外 TDR 段/CTX、吞吐、P95 服务延迟
四个维度划分 Pareto 层。先选未被其他候选全面支配的参数，再以归一化拥挤距离
保留不同权衡方向，最多选 3 组；必要时从下一层补足。完全相同时按参数内容 ID 确定性排序。
不会按“EWMA 领先其他方法的幅度”挑参数，也不承诺任何方法胜出。

对入选参数，在完整网格上取 epsilon 和记忆尺度各自的前一档、本档、后一档的组合。
已完成的粗搜组合跳过。额外加入预先固定的“未覆盖轴值”探测，使完整网格中
每个 epsilon 和每个记忆尺度至少出现一次（不保证所有交叉组合出现）：
默认每个需求策略补充 `(0.2,1)、(0.25,2)、(0.4,8)、(0.7,32)`。

默认最多新增 5,859 组，通常少于此上限，因为邻域互相重合、已有组合也会去重。
Valve 已在粗搜全覆盖，不做重复细搜。Plain 也不重复。
细搜计划在执行前保存，断点续跑不会因部分细搜结果改变同一轮计划。

### validate：固定候选的留出验证

训练结果（粗搜＋细搜）每个方法选最多 3 组，规则与上面一致；Plain 保留 1 组。
每个场景最多 13 个候选，在 **1 个与训练不重叠的数据区间 × 路由种子 7** 上各验证一轮，
最多 **819 组**。验证结果只报告，不反馈给细搜或候选选择。

训练与验证区间由映射前、完成基础过滤和交易哈希去重后的候选序号定义：

| 区间 | 合格候选序号（左闭右开） |
|---|---|
| train | [0, 200000) |
| validation_1 | [200000, 400000) |

每个区间、每个映射保序取前 10,000 CTX；不足时明确失败，不能用训练数据补足。
去重覆盖被跳过的前缀，防止源 CSV 的重复哈希造成训练/验证泄漏。
这些是不同的原始交易区间，但仍来自同一份 trace，不应当作完全独立的现实经济样本。

### 搜索规模说明

完整训练笛卡尔网格有 11,151 组；实际执行的是上述自适应子集，不声称找到全局最优。
粗搜＋细搜＋验证的保守上界是 9,513 个 trial，每个 10,000 CTX，规模仍然很大。
仅粗搜就有 28,350,000 CTX。因此默认虽支持从头跑完，但推荐按场景和余额分批。
程序不会在后台自动追加搜索；`--max-trials` 可限制本次新启动数。

## 冷启动与指标

保留现有策略的就绪规则：硬窗口满窗后开始，EWMA 至少观察 5 个不同块；χ 固定为 10。
短窗口只改变需求估计，不表示每块都再平衡。
10,000 笔在目标速率下约释放 84 个逻辑块，64 块窗口接近注入尾声才开始工作。
本轮适合快速探索，长记忆参数可能受冷启动影响；`--check` 会显示 `long_memory_caution=true`。
实际注入可能受源账户并发、主机、RPC、热点容量影响，实际指标单独记录。

每 trial 除全程指标外，还按预先固定的到达位置，将前 `80×120=9600` 笔标为 cold，
剩余仅 400 笔标为 post_warmup，并分别报告 Relay 比例和服务延迟 P95。
保留原来的 80 块分段边界以便识别这一限制，不能把这 400 笔解释为充分稳态验证。
这是到达序号分段，不是精确链高切片，也没有把预热交易从资金状态中删除。
Pareto 搜索使用全程四指标；分段结果用于检查长窗口是否主要输在冷启动。

报告还包括 TDR 事件/转移/金额、实际注入、backlog、分片满块比例和平均容量利用率。
已有 `e2e_secs` 属于服务阶段计时，不包含全部到达后排队。
低余额可能小于某些单笔金额，按每档余额统计这类交易，避免将所有 Relay 解释为净流耗尽。

完整性失败、交易数不符、重复/丢失、TDR 丢失转移、守恒失败或缺少容量指标的 trial
不能参与筛选。程序保留失败尝试并停止，不会跳过失败后假装完成搜索。
算法指标较差仍是有效研究结果，不会被当成运行失败。

## 如何运行

已安装的 brokerlab Python 环境和 Anvil 即可。从项目根目录运行：

```powershell
cd D:\BaiduNetdiskDownload\exp_anvil_broker_qwen\exp_anvil_broker_qwen

# 只看网格、规模和环境，不启动节点、不创建输出
python experiments/exp013_parameter_search/run.py --check

# 全部映射、训练及一个留出数据区间的预处理审计，不启动链
python experiments/exp013_parameter_search/run.py --prepare-only

# 推荐：先做一个余额、一个三热点场景的粗搜，每次最多运行 5 组
python experiments/exp013_parameter_search/run.py --balances 0.5 --scenarios three_hot6 --stage coarse --max-trials 5
```

上条命令结束会打印 `OUTPUT: ...`。之后继续同一次搜索，替换成真实输出路径：

```powershell
python experiments/exp013_parameter_search/run.py --resume "输出目录完整路径" --stage coarse --max-trials 5
```

该场景粗搜完成后，执行细搜和验证：

```powershell
python experiments/exp013_parameter_search/run.py --resume "输出目录完整路径" --stage refine
python experiments/exp013_parameter_search/run.py --resume "输出目录完整路径" --stage validate
```

或者让同一次搜索继续所有尚未完成阶段：

```powershell
python experiments/exp013_parameter_search/run.py --resume "输出目录完整路径"
```

不加任何筛选参数，会新建一次覆盖全部场景的完整分阶段搜索：

```powershell
python experiments/exp013_parameter_search/run.py
```

`--balances 0.1,0.5,1.0` 与 `--scenarios uniform4,three_hot5,three_hot6` 可选择子集。
网格列表在本目录 `config.yaml` 中编辑，普通标量可用 `--set exp.xxx=value`。
`--resume` 使用冻结的配置，不允许混入新的 --set/--balances/--scenarios/--config；
若要改变规模、资金、网格、端口或算法，创建新一次运行。
只启动后续阶段时，程序要求前置阶段完成，不会偷偷用部分结果挑选参数。

`--prepare-only` 的输出同样可以 `--resume`，复用准备好的输入文件。
运行日志、已通过 summary、工作负载与代码都有核验；源码、冻结配置或 trace 改变时拒绝续跑。
遇到失败可在原因消除后恢复，失败 trial 会创建新 attempt，旧日志保留。
同一输出目录有 PID/启动时间锁，防止两次恢复互相覆盖。Ctrl+C 会回收本次拥有的子进程树。
被强制杀死整个终端后的残留端口应核实归属后处理，程序不会杀其他实验。

快速工程检查：

```powershell
python experiments/exp013_parameter_search/run.py --smoke --max-trials 2
# 然后对打印的 smoke 输出目录使用 --resume，验证恢复流程。
```

`--smoke` 明确使用独立标签和端口 15600～15615，2 brokers、每方法 200 CTX，
一个三热点场景、每方法一个参数、一个留出窗口、一个种子，总共 10 trial / 2000 CTX。
它只检查五方法和阶段流程，样本太短，不能评价 EWMA 优势或长窗口参数。

## 文件与报告

- `config.yaml`：用户确认的候选范围及固定参数。
- `search.py`：候选生成、trial 参数编码、Pareto 分层、候选多样性选择、邻域与覆盖探测。
- `run.py`：数据准备、独立 trial 执行、冻结计划、检查点、恢复与报告。
- 每次输出在 `out/<时间戳>/`，包含 `resolved.yaml`、`manifest.json`、`metrics.csv`、`report.json`。
- `workloads/<区间>/<映射>/`：固定 workload、SHA256、完整桶映射、负载/金额/窗口审计。
- `plans/<映射>/<余额>/`：coarse/refine/validate 计划、父候选来源和完成标记。
- `trials/<内容ID>/attempt_NNN/`：每次尝试的配置、run.log、exp003 全部产物与结果。
  不同窗口即使共享旧版 arm 名称，也保存在不同 trial ID 目录，不会互相覆盖。
- `report.json`：当前阶段状态、成功/失败数、各场景各方法训练 Pareto 层、各留出窗口指标中位/范围。
  `trial_budget_reached` 代表本次数量上限到达，不代表整个搜索完成。
  只有 `status=complete` 才表示所选场景全部阶段完成，和 EWMA 是否胜出无关。
- `metrics.csv`：逐 trial 的全部参数与指标，可以按 balance/scenario/method/split/seed 筛选。
  同一种子下的不同验证参数使用完全相同输入；跨验证窗口的统计分别报告。

实验产物可能很多，特别是逐交易、余额与区块文件；分批执行并留意磁盘容量。
